# 期間中に測った数

このリポジトリの数は、すべてハッカソンの期間中（2026-11-02 から）に、作者の Mac（Apple シリコン）で測った物です。施設と職員はすべて架空です。README の「要点」は、ここから抜き出しています。

表を作る計算の部品（OR-Tools）は、同じ OS なら同じ入力から同じ表を作りますが、OS ごとに解き方の道筋が違います。Linux で同じ試算を回すと、ルールはどれも守ったまま、違う表と少し違う数になります（2026-11-05、GitHub の CI で分かりました）。そのため見本の施設の11月の表は、Mac で作った物をデータに入れて配り、試験は Mac で回しています。

## 次の勤務までの間が短い並び（14時間未満。遅番の次の日の早番など）

| 表 | 結果 |
|---|---|
| 見本の施設B「こもれびの家」（架空）の11月を貼って12月を作る | 貼った11月 22回 → 作った12月 0回。この並びを避けない作り方なら23回。作るのに約5秒。動かせないルール・本人の希望・運用の都合は全部守る |
| 人が組んだ表を模した架空の貼り付け（読めて作れた18通り。`uv run python tools/short_rest_sim.py`） | 貼った月の合計 475回。避けない作り方で作った翌月は 486回、避ける作り方では 0回。1通りあたり 0.2〜17秒 |
| 厚生労働省の標準様式（勤務形態一覧表）の記載例 | 特養28人 30回→1回、特定施設28人 26回→0回。夜勤・遅番などの1日の人数は、貼った月の幅のまま。計算は13秒ほど。グループホーム16人は6回→0回だが、短い勤務だけのパートの人が翌月ふつうの勤務に入るので、数に入れていない（直している） |

記載例は、厚生労働省の標準様式（令和6年3月告示分。https://www.mhlw.go.jp/stf/kaigo-shinsei.html ）の中にある、国が書き方の見本として作った表です。シフト記号表と一緒に `uv run python tools/standard_form_sim.py <貼り付け> <記号表>` で読みました（公式のデータはリポジトリに入れていません）。記載例は4週（28日）の表なので、このプログラムは2027年2月として読み、3月を作ります。7時間より短いパートの勤務の記号は、画面で［新しい勤務］を選んだ扱いにしました。特養の30回のうち26回は、遅番（12時〜21時）の次の日の早番（7時から）で、間は10時間です。記載例は見本なので、現場の頻度を表す物ではありません。

2026-11-05 の朝までは、特養も30回→0回と書いていました。この0回は、ユニットごとの人数しか見ていなかったため、作った3月に施設全体で夜勤0人の夜（毎日2人→0〜4人）ができていた表の数でした。ユニットごとに0人の日がある勤務は施設全体の人数も守るように直し（`tests/test_onboard_units.py`）、測り直した数が上の表です。

## 本物の Claude で確かめた数

| 場面 | 結果 |
|---|---|
| Claude Haiku 5.5 で一言を読む（撮影と試験の一言） | 36件を3周108回すべて、アプリの確かめに通した中身が用意と同じ。残業の穴埋めの一言を足した42件も、1周42回すべて同じ（中央1.7秒・最長3.4秒） |
| 同じく、指示文の例に使っていない別の言い方22件 | 3周66回すべて同じ（直す前は66回中64回） |
| 台本の3幕を本物の Claude で通す | 14件すべて通る（Claude を156回呼ぶ） |
| Claude Sonnet 5.5 で待機当番を組み立てる | 10回すべて同じ定義、1回2.2秒前後 |

直す前に本物の Haiku で36件を読ませると、合うのは16件でした。待機当番の一言を曜日の頼みと読む、研修の移動の元の日が抜ける、などです。指示文に例を足し、ぶれやすい所は、読み取りの値を基本にしたまま、外れやすい向き（私用の休みを動かせない扱いにする、など）だけをアプリの側で一言の言葉から直し、移動の元の日は表から補うようにしました（docs/failure-catalog.md）。

### ほかの当番も、言葉から組み立てられるか

待機当番のほかに、同じ組み立て役（Claude Sonnet 5.5）に当番や係の一言を10回ずつ組み立てさせました（`uv run python tools/build_duties.py --runs 10`。鍵が要ります）。

| 一言 | アプリの確かめを通った | 同じ形にそろった | 聞き返した |
|---|---|---|---|
| 毎月、入浴の日（月・木）は、日勤から入浴係を2人 | 10/10 | 10/10 | 0 |
| 毎月、土日祝は、遅番から送迎の当番1人。回数は翌月も覚えておいて | 10/10 | 10/10 | 0 |
| 毎月、夜勤の人のうち1人を、その夜の連絡係にして | 8/10 | 8/10 | 2 |
| 毎月、第2水曜の委員会の日は、日勤か早番から委員会の当番1人 | 0/10 | 0/10 | 10 |

「第2水曜」のような月の何回目の曜日は、今の欄の形では表せません。組み立て役は10回とも定義を作らずに聞き返し、間違った定義を黙って作った回はありませんでした。勤務の中で受け持つ係（入浴係など）は、休みの電話の当番には使いません。

## 費用（1回あたり）

本物の Claude を呼び、返事に付く使った量（トークン）を測りました（2026-11-05。各1回）。料金は公式の頁（https://platform.claude.com/docs/en/about-claude/pricing ）の Claude Haiku 5.5 入力 0.10ドル・出力 0.50ドル、Claude Sonnet 5.5 入力 2ドル・出力 10ドル（どれも100万トークンあたり）で、1ドル150円で計算しました。

| 呼び出し | 使った量（入力・出力） | 1回あたり |
|---|---|---|
| 一言を読む（Haiku 5.5。短い一言・長い一言・待機当番の一言） | 2,474〜2,514・37〜74 | 0.04円ほど |
| 表に無い仕組みを組み立てる（Sonnet 5.5。待機当番） | 652・147 | 0.42円ほど |
| 配った後にルールの理由の文を読み分ける（Haiku 5.5。理由1〜5件） | 264〜343・24〜84 | 0.01円ほど |

1か月に100回話すと4円ほどです。実際の会話では前の一言が付いて入力が少し増えるので、README では一言0.05円・100回で5円・組み立て0.5円と少し切り上げて書いています。

## Excel の勤務表の読み取り

作り話の表を3つの組で試しました（`tests/fixtures/pastes/`。現場によくある書き方を35通り）。最初の組は10通りのうち2通りしか読めず、直して10通りとも読めました。見せずに作った2つ目の組は10通りのうち6通りで、4つは黙って違う表になりました。3つ目の組でも黙って違う表が9つありました。翌月の表を貼った月と並べて違いを必ず見せる形に変えた後は、その9つのうち8つが止まるか正しく作れます（残る1つは、早番を「日勤と同じ」と答えた取り違え）。
