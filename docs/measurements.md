# 期間中に測った数

このリポジトリの数は、すべてハッカソンの期間中（2026-11-02 から）に、作者の Mac（Apple シリコン）で測った物です。施設と職員はすべて架空です。README の「要点」は、ここから抜き出しています。

表を作る計算に使っている OR-Tools（Google の計算のソフトウェア）は、同じ OS なら同じ入力から同じ表を作りますが、OS ごとに解き方の道筋が違います。Linux で同じ試算を回すと、ルールはどれも守ったまま、違う表と少し違う数になります（2026-11-05、GitHub の CI で分かりました）。そのため見本の施設の11月の表は、Mac で作った物をデータに入れて配り、試験は Mac で回しています。

記載例は、厚生労働省の標準様式（令和6年3月告示分。https://www.mhlw.go.jp/stf/kaigo-shinsei.html ）の中にある、国が書き方の見本として作った表です。シフト記号表と一緒に `uv run python tools/standard_form_sim.py <貼り付け> <記号表>` で読みました（公式のデータはリポジトリに入れていません）。記載例は4週（28日）の表なので、このプログラムは2027年2月として読み、3月を作ります。7時間より短いパートの勤務の記号は、画面で［新しい勤務］を選んだ扱いにしました。特養の30回のうち26回は、遅番（12時〜21時）の次の日の早番（7時から）で、間は10時間です。記載例は見本なので、現場の頻度を表す物ではありません。

市の記入例は、指定や更新の申請の様式と一緒に市が公開している表です（新潟市 https://www.city.niigata.lg.jp/iryo/kaigo/jigyousya_yousiki/chiikiservice/kousin_tiikimityaku.files/0701_chimitu_kinmukeitai.pdf の10ページ、津市 https://www.info.city.tsu.mie.jp/fukushi_kenkou/kaigohoken/1009832/1003073/1003083/1003088.html の勤務表とシフト記号表の記載例）。2026-11-05 に PDF から書き起こし、同じプログラムで読みました。名前の欄は作り話の名前に置き換えました。新潟市の表は、夜勤を「準（17時〜24時）」と「夜（0時〜9時）」の2つの記号に分けて書き、公休を「×」と書いています。記号表と一緒に貼ると、アプリは「夜」を明けと同じ、「準」を夜勤、「×」を休みと勧め、そのとおりに答えて作った数が上の表です。2026-11-05 の夜に直す前は、「夜」を夜勤の始まりと読み、準から夜へのつながりも短い並びに数えて45回→3回でした。

2026-11-05 の朝までは、特養も30回→0回と書いていました。この0回は、ユニットごとの人数しか見ていなかったため、作った3月に施設全体で夜勤0人の夜（毎日2人→0〜4人）ができていた表の数でした。ユニットごとに0人の日がある勤務は施設全体の人数も守るように直し（`tests/test_onboard_units.py`）、測り直した数が上の表です。

## 職員が30人を超える施設

その月の職員が30人を超える時は、表を作る計算（OR-Tools）を8つ並べて、決まった順で回します（取り込んだ時の人数ではなく、その月の人数で決めるので、後から30人を超えた施設にも効きます）。1つで探していた時は、大きな施設では時間内に最初の段の表が見つからず、運用の都合のルール（公休の数・夜勤の回数）を外して作ったり、作れなかったりしました。8つの中には、できた表の一部だけを解き直す探し方が入るので、短い並びが早く減ります。決まった順で回すので、同じ入力なら同じ表になります（下の施設はどれも2回作り、同じ表でした）。計算の量は8つの合計で数え、30人以下の施設の2倍にしました（2倍にする前は、短い並びが0〜2回残りました）。30人以下の月は今までどおり1つで探すので、表は1マスも変わりません。記載例3つ・試験用の9人の表・こもれびの家の表で、直す前と同じ表になることを確かめました。

国の様式の記載例（特養28人・特定施設28人）を写して、大きな施設を作りました。写すたびにユニット名と名前（職員001 の形）を変え、2つ目からはユニットごとに並びを何日かずらして、同じ並びの人を減らしています。100人の施設は、2つ目の特養から管理者・医師など4人を、2つ目の特定施設から介護職員以外の8人を写していません。どれも2027年2月として読み、3月を作りました。測ったのは 2026-11-05 の夜、作者の Mac です（直した後は負荷 約3、直す前は負荷 約3〜5）。

| 特養2つ 56人 | 58回→11回、27秒 | 58回→0回、16秒 |
| 特養2つ＋特定施設 84人 | 作れなかった（80秒） | 84回→0回、16秒 |
| 特養2つ＋特定施設2つ 100人 | 運用の都合を外して作った（ルールの外れ54か所）。108回→234回、72秒 | 108回→0回、19秒 |
| こもれびの家の見本を4つ写した32人 | 間の目安を外して作った。88回→83回、37秒 | 88回→0回、3秒 |

直す前に本物の Haiku で36件を読ませると、合うのは16件でした。待機当番の一言を曜日の頼みと読む、研修の移動の元の日が抜ける、などです。指示文に例を足し、ぶれやすい所は、読み取りの値を基本にしたまま、外れやすい向き（私用の休みを動かせない扱いにする、など）だけをアプリの側で一言の言葉から直し、移動の元の日は表から補うようにしました（docs/failure-catalog.md）。

### 例に使っていない現場の言い方

撮影と試験の一言は、作者が台本に合わせて書いた物です。それとは別に、現場の人がふだん口にする言い方でも読めるかを確かめました（`uv run python tools/everyday_phrasing.py --runs 3`。鍵が要ります。一言と正しい結果は `tools/everyday_phrases.json`）。言い方は、別の系統の AI（Codex の GPT-6 Sol）に、このアプリの指示文と例を見せずに書かせました。名前のある休みや勤務の変更、名前の無い一言、「明日」「来週の水曜」、ルールにしたい頼み、取り消しや言い直し、2人の入れ替え、名簿にない名前を混ぜています。1件ごとに見本の施設の11月の最初の状態から始め、今日を2026年11月5日（木）として、本物の Claude Haiku 5.5 で読ませました。

「正しく直した」は、頼まれた人のその日の勤務が正しくなり、しかも増えたルールが一言に出てきた人と頼まれた日だけに関わる時です。人数を守るためにほかの人のマスが動くのは、このアプリの作りなので数えません。

| 組 | 結果 |
|---|---|
| 組A（30件と、作者が書いた2件）。直す前に1回（11月5日の夜） | 30件のうち、正しく直した10件・聞き返した19件・読み違えて違う直しを入れた1件（「今月はもう夜勤、追加しないでね。今入ってる分はそのままで」を上限0回と読み、夜勤を全部外して19マス動いた） |
| 組A。直した後に3回（11月6日の朝） | 直すのが正しい15件は45回中39回正しく直した。聞き返すのが正しい17件は51回中45回聞き返し、残りの6回は筋の通るルールを入れた（「26日の夜勤、外して」を26日は夜勤にしない、など）。間違えて表やルールを変えたのは96回中0回 |
| 組B（20件）。組Aで見つけた所を直した後に初めて通した組。3回（11月6日の朝） | 直すのが正しい12件は36回中33回正しく直した。聞き返すのが正しい8件は24回とも聞き返した。間違えて表やルールを変えたのは60回中0回 |

組Aで見つけて直したのは次のとおりです。どれも `tests/test_everyday_phrasing.py` と `tests/test_swap.py` に、直す前のコードで落ちる試験があります。

- 「明日」「あさって」「来週の水曜」「今度の日曜」を、名前を伏せた後・送る前に表の月の日付へ置き換える（Claude には今日の日付を渡していないので、4件とも日付を聞き返していた）。月の外になる時は送らずに聞き、後ろに日付がある時・「来週の日曜」（週の始まりが人によって違う）・今日と同じ曜日の「今度の〜曜」は置き換えない
- 「14日の遅番、早番に変えて」を移す先の無い「移す」と読んだ時は、変える先として言った勤務が1つで、一言に出る人が1人以下の時だけその日を直し、分からなければ聞く（前はルールがぶつかって「見つかりませんでした」）
- 「追加しない」「そのまま」と言った回数の上限が0回なら、今の回数を上限にする（「外して」「0回」と言った時は0回のまま）
- 名前を言っていない一言（「私、13日の…」）は「誰の頼みか読み取れませんでした」と聞く。Claude が名簿の誰かを当てて返した時も聞く（3回に1回、名簿の最初の人と読んで6マス動いた）
- 2人の勤務の入れ替えを直せるようにした（前は「まだ扱えません」）。指示文は変えず、2人と日は一言の文から取る。指示文に足すと、入れ替えと関係ない「10日の早番、公休にしてもらえる？」を正しく直せたのが5回中5回から5回中2回に落ちたため

組Bは、組Aで見つけた所を直した後に初めて通した組です。その後、組Bで見つかった1件（「10日の早番、日勤に動かせます？」を、きびしくした決まりのせいでその日の変更と読めなかった）を直し、表を見ずに書かれて言った勤務が表と違う入れ替えの1件（組Aにも1件）は、表の勤務を見せて聞き返すのが正しいと付け直しました（理由は一覧に書いてあります）。

直せなかったのは、言い直しの日付（「25、あ、ごめん26日」。3回とも日付を聞き返した）と、「有給じゃなくて日勤で」「研修なくなったから、そこ日勤で」のように Claude が2つの頼みに分けて返した時（「頼みが混ざっています」と聞き返した）です。読み違えた時も、直した中身は画面の下と右のルールの一覧に出て、［ひとつ戻す］で戻せます。

### ほかの当番も、言葉から組み立てられるか

待機当番のほかに、同じ組み立て役（Claude Sonnet 5.5）に当番や係の一言を10回ずつ組み立てさせました（`uv run python tools/build_duties.py --runs 10`。鍵が要ります）。

| 一言 | アプリの確かめを通った | 同じ形にそろった | 聞き返した |
|---|---|---|---|
| 毎月、入浴の日（月・木）は、日勤から入浴係を2人 | 10/10 | 10/10 | 0 |
| 毎月、土日祝は、遅番から送迎の当番1人。回数は翌月も覚えておいて | 10/10 | 10/10 | 0 |
| 毎月、夜勤の人のうち1人を、その夜の連絡係にして | 8/10 | 8/10 | 2 |
| 毎月、第2水曜の委員会の日は、日勤か早番から委員会の当番1人 | 0/10 | 0/10 | 10 |

「第2水曜」のような月の何回目の曜日は、今の欄の形では表せません。組み立て役は10回とも定義を作らずに聞き返し、間違った定義を黙って作った回はありませんでした。勤務の中で受け持つ係（入浴係など）は、休みの電話の当番には使いません。

## 費用（1回あたり）

本物の Claude を呼び、返事に付く使った量（トークン）を測りました（2026-11-05。各1回）。料金は公式の頁（https://platform.claude.com/docs/en/about-claude/pricing ）の Claude Haiku 5.5 入力 0.10ドル・出力 0.50ドル、Claude Sonnet 5.5 入力 2ドル・出力 10ドル（どれも100万トークンあたり）で、1ドル150円で計算しました。

| 呼び出し | 使った量（入力・出力） | 1回あたり |
|---|---|---|
| 一言を読む（Haiku 5.5。短い一言・長い一言・待機当番の一言） | 2,474〜2,514・37〜74 | 0.04円ほど |
| 表に無い仕組みを組み立てる（Sonnet 5.5。待機当番） | 652・147 | 0.42円ほど |

1か月に100回話すと4円ほどです。実際の会話では前の一言が付いて入力が少し増えるので、README では一言0.05円・100回で5円・組み立て0.5円と少し切り上げて書いています。

## Excel の勤務表の読み取り

作り話の表を3つの組で試しました（`tests/fixtures/pastes/`。現場によくある書き方を35通り）。最初の組は10通りのうち2通りしか読めず、直して10通りとも読めました。見せずに作った2つ目の組は10通りのうち6通りで、4つは黙って違う表になりました。3つ目の組でも黙って違う表が9つありました。翌月の表を貼った月と並べて違いを必ず見せる形に変えた後は、その9つのうち8つが止まるか正しく作れます（残る1つは、早番を「日勤と同じ」と答えた取り違え）。
