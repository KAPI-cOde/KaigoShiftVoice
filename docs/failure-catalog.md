# 失敗の一覧（実際に起きたことだけ）

期間中に実際に起きた失敗を、「症状 → 誤った直感 → 正しい打ち手 → 確かめた試験」の形でまとめました。どれも git の履歴と [development.md](development.md) に元の記録があります。「誤った直感」は、直す前の作りがどんな考えで作られていたかを書いたものです。

## 1. 月の境目で翌月の表が作れなくなる

- **症状** 11月の表が「早・遅・日・日・夜」で終わり、12月1日の明けまで含めると6連勤になって、12月の表が作れなかった
- **誤った直感** 連勤はその月の表の中だけで数えれば足りる
- **正しい打ち手** 月末の夜勤は翌月1日の明けまで連勤に数える式を足し、翌月は前の月の末5日を受け取って作る
- **確かめた試験** `tests/test_nextmonth.py::test_l4_december_copy`、`tests/test_solver.py::test_s2_month_crossing`

## 2. 穴埋めを頼んだ人が別の日に入る

- **症状** 休みの電話の直しで、頼まれた人が翌日に入り、当日の日勤が1人足りないままの案が出た
- **誤った直感** 頼まれた人の入り方は、計算に任せれば自然に当日になる
- **正しい打ち手** 頼まれた人は、休む人と同じ日・同じ勤務に入る形に固定した（待機の案にも効く）
- **確かめた試験** `tests/test_act2.py::test_d4_wider_after_refused`、`tests/test_standby.py::test_d3_only_duty_moves`

## 3. 返す案を白紙から探すと、表が大きく変わる

- **症状** 引き受けた人に有給と短い連勤を返す案を白紙から探すと、約390マスが変わり、「遅番の次の日に日勤を置かない」ルールが7件外れた
- **誤った直感** 返す条件を足して解き直せば、返さない案に近い表が出てくる
- **正しい打ち手** 返さない案を計算の出発点に渡し、ほかの人の有給・5日続く勤務・飛び石は返さない案より増やさない条件を付けた。変わるのは5マス、外れは0件になった
- **確かめた試験** `tests/test_giveback.py::test_b1_both_plans_same_conditions`、`tests/test_act3.py::test_act3_flow`

## 4. 用意した返事では合っていたのに、本物の Claude では36件中16件しか合わない

- **症状** 録った返事で試験を回していた間は全部通っていた。本物の Claude Haiku 5.5 で読ませると、待機当番の一言を曜日の頼みと読む、研修の移動の元の日が抜ける、人の言い直しの前の方まで件にする、などで20件が違った
- **誤った直感** 用意した返事で通る試験があれば、本物でも同じように読める
- **正しい打ち手** 本物で読ませて比べるプログラム（`tools/record_replies.py`）を作り、指示文に決めと例を足し、元の日は表から補うようにした。3周108回とも合う所まで上げ、試験の返事を本物で録った物に入れ替えた
- **確かめた試験** `tests/test_act2.py::test_d1_standby_by_words`、`tests/test_t2.py::test_t2_11_person_restated`、`tests/test_utterance.py::test_act1_training_and_move`（本物の返事で回る）

## 5. ぶれをアプリの側で吸収しすぎる

- **症状** 休みの強さを一言の言葉だけで決めるようにしたら、「できるだけ」「どうしても」「きついから休ませてあげて」が、黙って別の強さになった
- **誤った直感** Claude の読み取りがぶれるなら、強さは全部アプリの言葉の決めで上書きした方が安定する
- **正しい打ち手** 読み取りの値を基本にし、外れやすい向き（私用の休みを動かせない扱いにする、「助かる」を「できれば」扱いにする）だけを言葉で直す形に戻した
- **確かめた試験** `tests/test_strength.py::test_day_off_strength`、`tests/test_strength.py::test_set_cell_external_fixed_kept_and_helpful_not_negotiable`、`tests/test_strength.py::test_count_strength`

## 6. 古い待機の案を了承すると、後の直しを上書きする

- **症状** 休みの電話の案を出した後に別の直しが入り、その後で古い案を了承すると、後の直しが消えた
- **誤った直感** 案を出した時の表をそのまま書き戻せばよい
- **正しい打ち手** 了承の時に表が変わっていたら、今の表から案を作り直す
- **確かめた試験** `tests/test_act2.py::test_astra1_stale_offer_is_rebuilt`

## 7. 配った後の何日分もの休みが、確認なしで表に入る

- **症状** 表を配った後に、何日分もの休みや「20日は遅番で」のような頼みを言うと、確認なしで表が変わった
- **誤った直感** 配る前と同じように、言えばすぐ直してよい
- **正しい打ち手** 配った後のほかの直しは、動くマスを見せて［これで直す］を押すまで表を変えない
- **確かめた試験** `tests/test_act2.py::test_astra2_multi_day_after_distribution_needs_ok`

## 8. 了承の途中で止まると、引き受けの記録が欠ける

- **症状** 了承を押した途中でアプリが止まると、表は直ったのに、引き受けの記録が残らなかった
- **誤った直感** 表を先に保存し、記録は後から足せばよい
- **正しい打ち手** 保存の順を「ルールの帳面 → 引き受けの記録 → 表」に変え、開き直した時に帳面から立て直す
- **確かめた試験** `tests/test_act2.py::test_astra3_crash_before_record_recovers`、`tests/test_utterance.py::test_recover_after_ledger_written`

## 9. 人を名指しした回数のルールが守られない

- **症状** 「今月は夜勤ゼロ」と名指しで言っても、全員向けの夜勤の回数の下限とぶつかって守られず、赤い知らせが出ていた
- **誤った直感** ルールは全部同じ重さで並べて解けばよい
- **正しい打ち手** 名指しの回数のルールは、言った側（上限か下限か）だけ全員向けを上書きする。本人の希望・期間の一部だけ・全員向けが動かせない決まりの時は上書きしない
- **確かめた試験** `tests/test_t2.py::test_named_count_overrides_only_its_side`、`tests/test_t2.py::test_t2_20_zero_this_month_only`

## 10. 台本の山場が、表を作り直したら消える

- **症状** 11月の表を作り直したら、12月の返さない案で小島さんの土日祝の夜勤がもともと0回になり（当時は土日祝の夜勤を減らして返していた）、「返す」が見せられなくなった
- **誤った直感** 試験は「数字が台本と同じか」を見ていれば足りる
- **正しい打ち手** 12月の計算の種（乱数の元）を施設の設定に固定し、試験は「1回以上から減る」の向きを確かめる形に強めた（返し方を変えた今は「有給が増え、いちばん長い連勤が短くなる」を確かめる）
- **確かめた試験** `tests/test_act3.py::test_act3_flow`

## 11. 声の漢数字で、日付と回数が読めない

- **症状** 手元の音声認識は「二十九日」「三回」と漢数字で返し、そのままでは日付と回数として読めなかった
- **誤った直感** 漢数字を全部算用数字に直せばよい
- **正しい打ち手** 数える言葉（日・回・月など）の前だけ直し、「一時的」「一人ずつ」は直さない
- **確かめた試験** `tests/test_voice_text.py::test_kanji_digits`

## 12. 返事が人を省くと、一言の人ではなく全員に効く

- **症状** 「岡田さん、15と16は法事で休み」の返事が人を省くと、全員の15日・16日が休みのルールになり、5人のマスが動いた
- **誤った直感** 返事の値が名簿にあるかを確かめれば、人の取り違えは防げる（人が無いことは「全員」の意味として通していた）
- **正しい打ち手** 一言に名簿の人が出ているのに返事が人を省いた時は、当てずに聞き返す。はじめは名前と呼び方の文字そのものだけで「人が出ている」を見ていたので、名前の頭だけ（「遠藤さん」）やかな（「おかださん」）で呼ぶとすり抜けた。伏せる処理と同じ見方（伏せた後に職員の番号があるか）と、「さん」などの呼びかけで見る形に変えた。「全員」「みんな」と言った時は聞き返さない。それでも、さんの無いかなの名前や「皆勤」ではすり抜け、「利用者さん」を含む全員向けのルールが止まった。人が出ているかを言葉で当てる考え方を続けるのをやめ、マスの頼みは人が無ければいつでも聞き返し、全員向けのルールは名簿の人が伏せられた時だけ聞き返す形に分けた。その後、全員向けのルールの側でかなの名前に「さん」を付けた一言がすり抜けると分かり、「さん」の前の語が名前でない語（利用者・みな）でなければ人が出たとみなす形を足した
- **確かめた試験** `tests/test_safety.py::test_bad_reply_changes_nothing`（nobody・nobody_count）、`test_nobody_reply_when_called_by_prefix_or_kana`、`test_nobody_cells_never_go_to_everyone`、`test_everyone_rule_with_san_word_is_not_blocked`、`test_person_rule_by_kana_or_kaikin_never_goes_to_everyone`

## 13. 読点の落ちた一言で、呼び方を伏せずに送る

- **症状** 呼び方のある職員で「ゆうちゃ20日休み」のように名前のすぐ後ろに数字が続くと、呼び方がそのまま Claude へ送られた
- **誤った直感** 名前の後ろは「さん」か読点か助詞が来るので、それだけを区切りにすれば足りる
- **正しい打ち手** はじめは区切りに数字と勤務の記号の字を足した。ところが再レビューで「ゆうちゃ来週休み」「遠藤午後休み」がまだ残ると分かった。後ろに続く言葉の幅は字を足しても塞ぎきれないので、やり方を変え、伏せた後の文に呼び方や名前の頭が残っていたら送らずに「『ゆうちゃ』は遠藤ゆうさんのことですか」と聞き返す形にした
- **確かめた試験** `tests/test_safety.py::test_mask_call_and_prefix_before_digits_and_shifts`、`tests/test_safety.py::test_mask_leftover_is_not_sent`

## 14. 名前でない語の一覧を広げたら、新しいすり抜けができた

- **症状** 全員向けのルールが「看護」に「さん」を付けた言い方や「休みをたくさん」で止まるので、「看護」「たく」「リーダー」などを名前でない語の一覧に足した。すると、名簿に無い人の呼び名「たく」に「くん」を付けた人ごとのルールや、かなの名前に「リーダー」と「さん」を付けた言い方が、返事が人を省くと全員のルールになった。「たく」「リーダー」は後で一覧から外した
- **誤った直感** 止まる言い方を一覧に足していけば、止まらずに済み、すり抜けも増えない
- **正しい打ち手** 行き止まりは聞き返しの文の側で消す（ルールの時は「全員と付けて」と添える）。一覧は名前と重なりにくい職種の語だけにとどめ、名前の一部にもなる語（たく）や後ろに付く役職（リーダー）は足さない。止まる側に倒れても、言い直せば通るので害は小さい
- **確かめた試験** `tests/test_safety.py::test_nickname_or_title_rule_never_goes_to_everyone`、`test_nobody_clarify_tells_how_to_say_everyone`、`test_everyone_rule_with_job_word_is_not_blocked`

## 15. 点検を流した後に記録を書き足し、点検が止まる状態でコミットした

- **症状** 試験と公開前の点検が ok になった後に、レビューの指摘を記録へ書き足してコミットした。記録の中で職種の語に「さん」を付けて書いたため、点検が名前かもしれない語として4件止める状態になっていた。コミットの文と記録には「点検 ok」と書いていた
- **誤った直感** 文書だけの書き足しなら、点検の結果は変わらない
- **正しい打ち手** 点検とコミットを1つのコマンドでつなぎ、点検が ok の時だけコミットが進むようにする（`uv run python tools/check_public.py && git commit`）。記録では、名前でない語にも「さん」を付けずに書く
- **確かめた試験** 同じ誤りを捕まえる試験は無い。運用で防ぐ（点検 `tools/check_public.py` とコミットを1つのコマンドでつなぐ）。周10で書き方を直した後の点検は ok


## 16. 見本では通る取り込みが、現場の書き方では黙って違う表を作る

- **症状** Excel の勤務表を貼るだけで施設を作る入口を、架空の見本1つで作って試験も通した。現場によくある書き方10通りで測ると、通ったのは2通り。施設独自の記号（A・N・①）では、夜勤のルールが落ちたまま「表ができました」と出た。その10通りに合わせて直すと10通りとも通ったが、見せていない別の10通りで測り直すと6通りで、4つはエラーも出ずに中身が違った（宿直・職種の見出しの行など）。3組目でも、早番が「早1・早2」の2種類ある表などで、黙って違う表が9つ出た
- **誤った直感** 貼った表からルールを見つけ損ねなければ、施設を写し取れる。落ちた書き方を1つずつ塞げば、いずれ全部通る
- **正しい打ち手** ルールを完全に見つける前提をやめた。できた翌月を貼った月と並べ、違う所（1日の人数の幅・夜勤の翌日・人ごとの勤務・公休の数）を作った後の画面に必ず赤で出し、アプリのいつもの一言で直せるとつなげた。毎日いた勤務が翌月に1回も無い時だけは「できた」と言わない。直すたびに、見せていない組で測り直した
- **確かめた試験** `tests/test_onboard.py`（`tests/fixtures/pastes/` の32通り）、`tests/test_onboard.py::test_出口の確かめ_毎日いた勤務が翌月に無ければできたと言わない`

## 17. 点検を add の前に流し、新しい試験のファイルの名前を見落とした

- **症状** 新しい試験のファイルを足したコミットで、点検を流してから `git add` した。点検は追跡中のファイルしか見ていなかったので、新しいファイルの中の許可外の名前を見落とし、「点検 ok」と書いてコミットした。GitHub の CI（P1）が落ちて分かった
- **誤った直感** 点検が ok なら、これからコミットする物は全部確かめた
- **正しい打ち手** 点検が、まだ add していない新しいファイルも見るようにした（`git ls-files --cached --others --exclude-standard`）。順番に頼らず、どの順で流しても見落とさない形にした
- **確かめた試験** `tests/test_check_public.py::test_untracked_new_file_is_checked_too`。直す前のファイルで新しい点検が止まるのを確かめた

## 18. 名前でない語の一覧を広げたら、また実名を伏せずに送る抜け道ができた（14の2回目）

- **症状** 「お子さんの熱で休み」が名簿にない名前「子」で止まるので、家族の言葉（子・孫・旦那など）を名前でない語に足した。直後に自動のセキュリティレビューが、「よし子さん」「とも子さん」のようにひらがなに続く名前まで名前でないとみなし、名簿にない人の名前を伏せずに Claude へ送ると指摘した。前からある一覧の語（母・娘・利用者など）にも同じ抜け道があった。助詞の一覧で区切りを当てる直しも、「とも子」の「も」を助詞と取り違えた
- **誤った直感** 名前でない語を一覧に足せば、止まらずに済む。区切りは助詞の一覧で見分けられる
- **正しい打ち手** 迷ったら止める側に作り直したが、レビューは3回目も抜け道（「12日とお子さん」「ゆー子さん」）を見つけた。同じ前提の直しが2回外れたので前提を確かめると、前の字が名前の一部か助詞かは、字からは原理的に見分けられなかった。見分けるのをやめ、名前でない語の前にひらがななどが続く所は、その字ごと「（家族）」などに置き換えてから送る形にした。名前の一部だったとしても外へは出ず、人が読み取れなければ今どおり聞き返す。同じ種類の失敗が2回目なので、一覧の全部の語に9通りの名前の頭と4通りの前置きを付けて、名前の頭を送らないことを確かめる試験にした
- **確かめた試験** `tests/test_safety.py::test_every_not_name_word_after_hiragana_still_stops`、`test_hiragana_name_ending_in_family_word_still_stops`、`test_family_words_are_not_unknown_names`
