# 作り方の記録（Claude Code を中心にした開発）

このリポジトリのコードは、ハッカソンの期間中（2026-11-02 から）に Claude Code で新しく書きました。アイデアと仕様の文書は期間の前にリポジトリの外で考えたもので、ここには入れていません。

## 役割の分け方

| 担当 | 受け持ち | 理由 |
|---|---|---|
| メインの Claude（Opus） | 設計の判断、データの形、ソルバーと保存の芯、委任した物の検収 | 判断が要る所を1か所に集め、ぶれを防ぐため |
| Sonnet のサブエージェント | 画面（HTML）を作り、見えないブラウザで撮って自分で見て直す | 画面は量が多く、仕様が固まっていれば任せられるため |
| Haiku のサブエージェント | CI の点検（許可した名前の一覧と鍵の形）のような軽い実装 | 速く安く、手順が決まった作業に向くため |
| 別系統のモデル（敵対レビュー） | 区切りごとの差分を、壊す側の目で読む | 同じモデルだけで確かめると、同じ見落としが残るため |

委任した物は、メインが差分を読み、試験を流し、画面は撮った画像を見てから取り込みます。報告の文だけで合格にしません。

## 敵対レビューの使い方

指摘には「起きる条件・起きやすさ（0〜10）・影響（1〜10）」を付けてもらい、起きやすさは「この施設の使い方で、その条件が実際に起きるか」で付けます。直すのは、掛け算が20以上か、影響が8以上の物だけです。まれな場合に備えた作り込みで仕様が膨らむのを防ぐためです。

期間中に直した指摘の例は次のとおりです。

- 休みの電話の古い案を了承すると、後の直しを上書きした（3×9）
- 配った後に何日分もの休みが、確認なしで表に入った（5×8）
- 了承の途中で止まると、引き受けの記録が欠けた（保存の順を「帳面 → 記録 → 表」に変え、開いた時に立て直す）
- ［変える（話す）］が、確定済みの前の月のルールまで書き換えた（元のルールを前の月の末で閉じ、翌月から新しいルールを足す形にした）
- 画面に「送るのは名前を伏せた一言だけ」と書いていたが、「さん」の付かない名簿外の名前は伏せられない（言い方を実際の動きに合わせた）

見送った指摘も、起きやすさと影響の点と一緒に記録に残しています。

## 試行錯誤で変えたこと

試験と画面の撮影で見つかり、直したことです。

- **月の境目の罠。** 11月の表が「早・遅・日・日・夜」で終わり、12月1日の明けで6連勤になって、12月の表が作れなくなった。月末の夜勤は翌月1日の明けまで連勤に数える式を足した
- **穴埋めの人が別の日に入る案。** 休みの電話の直しで、頼まれた人が翌日に入り、当日の日勤が1人足りないままの案が出た。頼まれた人は、休む人と同じ日・同じ勤務に入る形に固定した
- **台本の山場が消えた。** 11月の表を作り直したら、12月の返さない案で小島さんの土日祝の夜勤がもともと0回になり、「返す」が見せられなくなった。種（計算の乱数の元）を測り直して12月の分を固定し、試験は「1回以上から減る」を確かめる形に強めた
- **待機の人の代わりに広げる時。** 待機の人に断られたら、表も記録も変えずに「待機の人だけでは埋められません。ほかの人に頼む案も見ますか」と聞き、その日に休みの人へ1人ずつ頼む形にした
- **声の数字。** 手元の音声認識は「二十九日」「三回」と漢数字で返すので、数える言葉の前だけ算用数字に直した（「一時的」「一人ずつ」は直さない）
- **本物の Claude で読むと、36件のうち16件しか合わなかった。** 用意した返事で試験を回していた間は見えなかった。待機当番の一言を曜日の頼みと読む、「木曜は」を日付の型にもする、研修の移動の元の日が抜ける、人の言い直しの前の方まで件にする、などだった。指示文に決めと例を足し、元の日は表から補うようにして、36件を3周108回とも合う所まで上げた。指示文の例に使っていない別の言い方22件も用意して測った（3周66回とも合う）
- **ぶれを手元で吸収しすぎた。** 休みの強さを一言の言葉だけで決めたら、「できるだけ」「どうしても」「きついから休ませてあげて」が黙って別の強さになると、敵対レビューで指摘された。読み取りの値を基本にし、外れやすい向き（私用の休みを動かせない扱いにする、「助かる」を「できれば」扱いにする）だけを言葉で直す形に戻した

## 守りのしくみ

- コミットの前に、手元のフックが実在の名前・鍵の形・メールアドレスを止めます。CI では、許可した名前の一覧と鍵の形だけを点検します
- Claude へ送る前に、名簿の名前を「職員01」の形に置き換えます。名簿にない名前に「さん」が付いていれば送らずに聞き返し、近い名前があれば候補を出します（候補は手元の名簿から出し、Claude には送りません）
- Claude の返事は候補として扱い、型・人・日・勤務・回数をアプリのプログラムが確かめます。返事が途中で切れた時は、表もルールも変えずに一言を残し、送り直せます

## 試験

`uv run pytest -q` で109件が回ります（Claude は呼ばず、本物の Claude で録った返事で回ります。鍵があれば `SHIFTVOICE_LIVE=1` で台本の3幕を本物で通せます）。台本の通し（1幕〜3幕）、言い換えと失敗の優先の10件、ルールの見直し、引き受けの記録、保存の途中で止まった時の立て直しを含みます。作者が作り話の台本を読んだ声での試験は、録音を手元に置いた時だけ動きます（録音はリポジトリに入れていません）。
